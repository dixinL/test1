# 申万行业趋势分析工具 · 一期可执行方案

> 技术栈：**Python + AkShare + SQLite/Excel 双存储**
> 一期目标：手动触发，完整跑通**全部申万二级行业板块（约 130 项，实测 akshare 1.18.94 返回 131 项，数量随版本浮动）**的指数点位拉取、趋势计算、双存储与 Excel 导出。

## 二、架构与数据流

```
AkShare 拉申万二级行业指数(点位，不复权) ──► SQLite(price 表：唯一事实源，点位每交易日一行)
                        │
                        ▼
        第一层：每窗口 MA + 线性回归斜率 + R²(按交易日窗口)
        用「每板块 × 每窗口」独立 ε(存 epsilon 表) 判 UP/DOWN/FLAT
                        │
                        ├─► SQLite(trend 表：每次计算明细，可追溯)
                        │
                        ▼
        第二层：把每个板块的 6 个窗口方向整理成一行(每板块一行)
        统计跨周期一致性(up_count/down_count/连续性)，出 UP/DOWN 双关注榜
                        │
                        └─► 导出 Excel 快照 (7 个明细 sheet + 汇总 sheet)
```

**职责分离**：SQLite 存**事实**（不重复、可增量、可追溯、易扩批量），Excel 出**视图**（当日交付物）。
**两层设计**：第一层的 ε 每板块独立，只为「方向判定不失真」；第二层整理跨周期趋势一致性、辅助发现连续趋势（辅助工具定位，不输出买卖决策）。见 §五。

## 三、SQLite 表设计

**表 1 `price`（指数点位，唯一事实源）**

| 字段 | 类型 | 说明 |
|---|---|---|
| sw_code | TEXT | 申万二级行业代码，**纯数字** 6 位字符串，如 `'801016'`（上游 `sw_index_second_info()` 返回的"行业代码"是 `801016.SI` 形态，带 `.SI` 后缀；落库前需剥掉后缀并以纯数字为主键） |
| sw_name | TEXT | 板块名称，如 '农产品加工'（冗余留存，便于阅读/导出） |
| trade_date | TEXT | 交易日 'YYYY-MM-DD' |
| close | REAL | 当日收盘点位 |
| | | 主键 `(sw_code, trade_date)`，天然去重 |

> **定位：`price` 存全历史，增量 append。** 首次运行把 `index_hist_sw` 返回的全量（1999 至今）一次性灌入；之后每次查该板块 `MAX(trade_date)`，仅把更新的行 `INSERT OR IGNORE` 追加，磁盘只增量写。主流程与探针**都从本表读**，探针不再单独触网。约 130 个板块 × 约 2500 交易日 ≈ 33 万行、几十 MB，SQLite 无压力。

**表 2 `trend`（计算明细，同一天重跑覆盖）**

| 字段 | 类型 | 说明 |
|---|---|---|
| sw_code | TEXT | 申万二级行业代码 |
| sw_name | TEXT | 板块名称 |
| calc_date | TEXT | 计算基准日（当天） |
| window | INTEGER | 窗口：10/30/60/90/180/360 |
| ma | REAL | 该窗口均线值 |
| slope | REAL | 线性回归斜率（原始，仅留档） |
| slope_norm | REAL | 归一化斜率（斜率/窗口内均价，去量纲，见 §五） |
| r_squared | REAL | 回归拟合优度 R²（0~1），趋势"有多干净/确定"，第二层参考 |
| price_vs_ma | REAL | (最新点位-MA)/MA，点位相对均线偏离 |
| epsilon | REAL | 判定时该 (板块,窗口) 用的死区阈值，留痕 |
| direction | TEXT | 'UP' / 'DOWN' / 'FLAT' / 'N/A'(数据不足) |
| created_at | TEXT | 运行时间戳 |
| | | 主键 `(sw_code, calc_date, window)`，UPSERT 覆盖，同一天重跑不产生重复行（幂等） |

**表 3 `epsilon`（每板块 × 每窗口的死区阈值，由探针生成）**

| 字段 | 类型 | 说明 |
|---|---|---|
| sw_code | TEXT | 申万二级行业代码 |
| window | INTEGER | 窗口 10/30/60/90/180/360 |
| epsilon | REAL | 该板块该窗口的死区阈值 |
| quantile | REAL | 生成时用的分位数（默认 0.40），留痕 |
| source | TEXT | 'probe'(探针自动) / 'manual'(手动覆盖) |
| updated_at | TEXT | 更新时间 |
| | | 主键 `(sw_code, window)`；探针 UPSERT 写入，可选不覆盖 source='manual' 行 |

`price` 每板块每交易日一行，约 130 个板块 × 360 天 ≈ 4.7 万行，十年也就几十万行、文件几十 MB 量级——存储与同质化可控。

## 四、节假日问题的澄清

申万行业指数在周末/节假日**不发布点位**（跟随 A 股交易日），数据源根本不返回这些天。因此：

- 不需要"给节假日补一个价"，也不需要 hack 填充。
- 均线/回归一律按**交易日窗口**计算：`window=10` 指"最近 10 个交易日"，而非 10 个自然日。取 `ORDER BY trade_date DESC LIMIT N` 即可。
- "节假日取最近开盘日价格"在交易日序列下自动成立——序列里本就只有开盘日。

> **落库与计算取数分离**：`price` 表落**全历史**（首灌全量、之后增量 append，见 §三）；主流程**计算时**再从库里 `ORDER BY trade_date DESC LIMIT` 截取最近约 375+ 交易日（覆盖 360 交易日窗口并留余量）。计算窗口用交易日个数，非自然日。所谓"550 自然日"仅是这层本地取数窗口的粗略圈定，不是网络请求范围（接口只能全量返回）。

## 五、判断标准（两层设计）

系统把趋势分析拆成两层解决（本工具定位为辅助/基础工具，不输出买卖决策）：
- **第一层 · 方向判定**：每个窗口它在不在上行？（每板块用自己的 ε，保证信号不失真）
- **第二层 · 跨周期整理**：一个板块六个周期的趋势是否一致/连续？（整理呈现，越一致越值得关注）
ε 每板块独立只是"降噪门槛"；第二层做的是把各周期方向整理成可读的一致性画面。

> **价格口径：指数收盘点位，不复权**。基础对象是申万二级**行业指数**（点位，非可交易基金），成分股分红已在指数编制中处理，指数本身不涉及除息跳空，故**不做复权**（无 qfq）。

### 五之一、第一层：方向判定

> **数据接口事实确认（写代码前已对齐 AkShare 实际接口）**：
> - 申万二级行业列表：`ak.sw_index_second_info()`，无入参，返回字段含「行业代码（形如 `801016.SI`）、行业名称、上级行业、成份个数、估值指标」，二级约 130 项（实测 akshare 1.18.94 为 131 项，数量随版本浮动，代码按实际返回动态遍历）。
> - 历史点位：`ak.index_hist_sw(symbol: str, period: str = "day")`，`symbol` 为**纯数字**指数代码（不带 `.SI`），`period ∈ {"day","week","month"}`；**接口不接受起止日期入参**，一次性返回该指数从 1999 年至今的全部历史；返回字段：`代码 / 日期 / 收盘 / 开盘 / 最高 / 最低 / 成交量 / 成交额`。本工具落 `price` 表只取 `代码 → sw_code`、`日期 → trade_date`、`收盘 → close`。
> - 实时行情（可选，本期不依赖）：`ak.index_realtime_sw(symbol)`，`symbol` 取 `"二级行业"` 等。
> - 申万指数本身无复权概念，**不使用 qfq**。
> - **接口只能全量返回、无法按区间请求**：`price` 落全历史（首灌全量、之后本地增量 append）；主流程计算时再从库里本地截取最近约 375+ 交易日，探针读库全历史。差异都在**本地裁剪**，不是靠接口传 start/end。


对每个窗口做一元线性回归 `close = a·t + b`，其中 `t` 取 **0,1,2,…,N-1 的交易日整数索引**（非自然日），得斜率 `a`，然后：

1. **归一化斜率** `slope_norm = a / mean(close_in_window)` —— 去量纲，表示"日均涨跌百分比"，跨标的、跨周期可比。（原始斜率 `a`/`slope` 因带量纲不可比，仅留档，不参与任何判定与排序。）
2. **拟合优度** `R²` —— 回归顺带算出，衡量趋势"有多干净"，锯齿震荡即使斜率不为 0，R² 也低。
3. **价格相对均线** `price_vs_ma = (最新收盘点位 - 本窗口 MA) / 本窗口 MA`。"最新收盘点位"指最近一个交易日的指数点位；每个窗口各自与自己的 MA 比。
4. **叠加判定**（两个信号同向才算趋势；ε 为**对称双边**阈值，只有一个正数值，UP 用 `>ε`、DOWN 用 `<-ε`）：

```
UP    ： slope_norm >  ε(sw_code,window)  且  price_vs_ma >  0
DOWN  ： slope_norm < -ε(sw_code,window)  且  price_vs_ma <  0
FLAT  ： 其余（含两信号打架、斜率在死区内）
N/A   ： 该窗口交易日不足 W（数据不足，不判定，照常输出其他窗口）
```

**死区阈值 ε —— 每板块 × 每窗口独立，数据驱动**

- 不用硬编码单一 ε。`slope_norm` 虽已消除点位量纲，但**没消除波动率量纲**：稳健板块（如公用事业）分布窄、高波动板块（如半导体、券商）分布宽。用同一绝对阈值会对稳健板块太松（假信号泛滥）、对高波动板块太紧（漏判），FLAT 占比失控。
- **方法（分位数法，规则统一、数值因板块而异）**：对每个板块、每个窗口，取其历史 `|slope_norm|` 分布的某分位数（默认 **40% 分位**）作为 ε。业务含义恒定 = "历史约 40% 时间判 FLAT、60% 判趋势"，对所有板块一致。
- ε 由 §七探针脚本生成，存入 `epsilon` 表（每板块 × 每窗口一行），主流程按 `(sw_code, window)` 查表取用。分位数为唯一可调参数；可为某行手动写死（`source='manual'`）覆盖。

### 五之二、第二层：跨周期趋势整理（辅助工具定位）

**定位澄清**：本程序是**辅助/基础工具**，第二层不是"选最值得买板块的选股引擎"，而是**对一个板块在各周期上的趋势做整理与呈现**。核心关注点是**跨周期的方向一致性/连续性**——若一个板块在多个周期上呈现连续一致的趋势，就更值得被关注（挣钱是隐含目标，不是程序直接输出买卖决策）。

**整理维度**（排序单元 = 每板块一行，六个窗口方向平铺）：

| 维度 | 指标 | 作用 |
|---|---|---|
| 跨周期方向 | 6 个窗口各自的 `direction` | 平铺成一行，直观看整体画面 |
| 趋势一致性 | `up_count` / `down_count`（六窗口中判 UP/DOWN 的个数） | 越集中一个方向，趋势越一致、越值得关注 |
| 连续性 | 从长到短（360→10）或从短到长是否**方向连贯不反转** | 连贯不反转 > 中间夹杂 FLAT > 方向打架 |
| 强度参考 | 各窗口 `slope_norm`、`R²` | 辅助参考，不作为唯一排序键 |

**呈现规则（UP + DOWN 双榜）**：
- **UP 关注榜**：列出 UP 窗口数较多的板块，按"一致性（`up_count`）→ 强度（`slope_norm` 均值）"排序，方便发现连续上行的行业。
- **DOWN 关注榜**：对称地按 `down_count` 整理下行连续板块（规避/减仓参考）。
- 排序服务于"整理呈现"，不产生买卖指令。

> 说明：一期跑全部约 130 个申万二级板块，双榜可真实横向对比，能直接看出哪些行业跨周期一致上行/下行。"每板块一行 + 跨周期一致性"结构与 `r_squared` 列定稿落地，二期可平滑扩到三级。一致性统计口径（up_count/down_count/连续性）放配置，先给默认，后续可调。

## 六、Excel 输出

每次运行导出一个文件 `sw_trend_YYYY-MM-DD.xlsx`，含 **7 个明细 sheet + 1 个汇总 sheet = 共 8 个 sheet**（原始需求为 7 个明细，汇总为额外新增）：

- **Sheet1 `点位`**：各申万二级板块最近交易日的收盘点位快照 `sw_code, sw_name, trade_date, close`（一期覆盖约 130 个板块，每板块一行）。
- **Sheet2~7 `MA10 / MA30 / MA60 / MA90 / MA180 / MA360`**：每周期一张，列出**全部板块**在该窗口的结果 `sw_code、sw_name、MA、原始斜率 slope(仅留档)、slope_norm、R²、ε、price_vs_ma、方向(UP/DOWN/FLAT/NA)`，按 `slope_norm` 排序，一眼看出该周期最强/最弱行业。
- **Sheet8 `汇总`（第二层输出，每板块一行）**：一行平铺该板块六个窗口的方向，附 `up_count / down_count / 连续性` 等一致性指标，并按 UP/DOWN 双关注榜的规则整理（见 §五之二），作为跨周期一致性总览。

同批数据同时写入 SQLite `trend` 表（同一天重跑覆盖），Excel 仅作快照。

## 七、ε 探针脚本（阈值数据支撑，先行落地）

**目的**：不猜阈值，用**每个申万二级板块**的真实历史算出各窗口 `slope_norm` 分布，据此为每个板块定 ε。

**脚本 `probe_epsilon.py` 做的事**：

1. **数据来源：优先读本地 `price` 全历史，不重复触网。** 探针从 `price` 表读每个板块的全部历史点位；仅当某板块在 `price` 中缺失（库空首次运行）时，才调 `index_hist_sw` 首灌全量并写入 `price`。因此探针与主流程**共用同一份 `price`**，探针一般 0 次额外网络请求。ε 是慢变量，**建议低频运行**（如每月/每季一次），日常只跑主流程增量。
   - **首灌判断按板块粒度**：对每个板块单独查 `SELECT MAX(trade_date) FROM price WHERE sw_code=?`，为空才对**该板块**首灌——不能用"整张 `price` 表非空就跳过"，否则曾单独跑过个别板块(如 `main.py --code 801016`)时，会误判其余板块已灌好而永久漏拉。逐板块判断可在库空/部分/全满任意状态下自愈补齐。
   - **幂等，无需手动清理**：写入统一用 `INSERT OR IGNORE`，主键 `(sw_code, trade_date)` 会把重复行直接忽略。库里已有数据时再跑探针不会重复插入，即便退化成"全量重灌"结果也一致。
2. 对每个板块、每个窗口 W ∈ {10,30,60,90,180,360}，滚动计算历史每一天的 `slope_norm`（回归斜率 / 窗口内均价），得到该 (板块,窗口) 的 `slope_norm` 时间序列。
3. 对每个 (板块,窗口) 的 `|slope_norm|` 计算分位数：默认取 **40% 分位** 作为 ε；同时可打印 **10% / 25% / 40% / 50% / 60% / 75% / 90%** 便于抽查分布。
4. 抽样打印若干板块：取 40% 分位作 ε 时各窗口的历史 **UP / DOWN / FLAT 占比**。⚠️ 注意：此占比是**仅按斜率分位的近似估计**，未叠加实际判定中的 `price_vs_ma` 同向条件，故真实 FLAT 占比会**更高**、UP/DOWN 会更低——占比仅供判断分布形态，不等于主流程实际输出。
5. 逐 (板块,窗口) **UPSERT 写入 SQLite `epsilon` 表**（`source='probe'`），主流程直接查表取用；可选同时写出 `data/epsilon_probe.csv` 备查。
6. 历史不足以支撑某窗口（如新板块凑不满 360 交易日）的 (板块,窗口)，记录告警并跳过该行，不写入无效 ε。

**产出用途**：全部板块的 ε 一次性落 `epsilon` 表；无需人工誊抄。此脚本**独立运行、不改主流程逻辑**，但与主流程**共用 `price` 表**（读同一份历史，不各拉各的）。

**执行**：`python probe_epsilon.py`

## 八、代码结构与执行方式

```
sw2-trend-analysis/
├── config.py          # 窗口、ε 分位数(默认0.40)、一致性口径、计算取数窗口(交易日数)、路径（板块列表运行时从 AkShare 获取）

├── analyze.py         # 第一层：MA+回归斜率+R²+归一化+查 epsilon 判方向；第二层：跨周期一致性整理+双榜
├── export_excel.py    # openpyxl 写 点位 sheet + 6 个 MA sheet(全板块) + 汇总 sheet
├── probe_epsilon.py   # ε 探针脚本（见 §七，先行/独立运行，逐板块写入 epsilon 表）
├── main.py            # 手动触发入口：fetch → analyze(两层) → 落库 → 导出 → 打印运行摘要
├── requirements.txt   # akshare, pandas, openpyxl (sqlite3 为内置)；建议固定小版本范围
└── data/
    ├── sw.db          # SQLite（price / trend / epsilon）
    ├── epsilon_probe.csv  # ε 探针输出（可选）
    └── exports/       # Excel 快照
```

- **触发方式**：一期手动 `python main.py`（可选 `--code <sw_code>` 只跑单个板块，默认全部二级板块）。
- **增量逻辑**：逐板块查 `price` 最新日期 → 库空则首灌全量、非空则拉全量后本地只 append 比最新日期新的行(`INSERT OR IGNORE`) → 校验(去 null/异常涨跌幅)去重写入 `price`(**存全历史**) → 计算时从库里 `ORDER BY trade_date DESC LIMIT ~375` 取数、重算 6 窗口(MA+斜率+R²+方向) → UPSERT `trend` + 第二层跨周期整理 → 导 Excel。
- **幂等原则**：同一天重复触发结果一致、不产生重复行（依赖 price 去重 + trend UPSERT）。
- **AkShare 接口（写代码前已对齐实际签名）**：
  - `ak.sw_index_second_info()`：取申万二级行业列表（无入参，约 130 项、实测 131，`行业代码` 形如 `801016.SI`）。
  - `ak.index_hist_sw(symbol="801016", period="day")`：逐板块拉日线点位（`symbol` 纯数字，`period ∈ {"day","week","month"}`；**接口无起止日期入参**，一次返回该指数从 1999 至今的全部历史 → 落 `price` 全历史；主流程计算取数与探针读数都在**本地裁剪**；**不复权**）。

## 九、一期范围界定

**做**：全部申万二级板块（约 130 项，实测 131）、手动触发、`price` 存全历史(首灌全量+增量 append+校验)、6 窗口 MA+归一化斜率+R²+方向判定(每板块独立 ε)、第二层跨周期一致性整理+UP/DOWN 双关注榜、三表双存储(探针与主流程共用 `price`)、8 个 sheet Excel(7 明细+1 汇总)、ε 探针脚本。
**一期不做**：申万三级下钻（二期按需，见下）、定时调度、Web 看板、买卖决策/交易信号输出、收益回测调优（ε 分位数与一致性口径先用默认，二期回测微调）、备用数据源兜底。

> **申万三级下钻（二期）**：三级约 350+ 个，问题在于部分子行业指数历史短/不连续、分类会修订、高相关板块易刷屏。二期建议做成"可选下钻"——在二级一致性榜里选中某个二级，再单独拉其下三级细看；历史不足的三级用已有 `direction='N/A'` 降级机制兜底。表结构（`sw_code`/`sw_name`）已通用，扩三级无需改 schema。

## 十、推进顺序建议

1. 先写并运行 `probe_epsilon.py`：取申万二级列表 → 读 `price`(库空则首灌全量历史点位、不复权，写入 `price`) → 为每个板块各窗口算 `slope_norm` 分布并写入 `epsilon` 表。此步同时完成 `price` 全历史首灌，主流程后续复用。
2. 据探针结果确认 `config.py` 的分位数默认值（如需微调）。
3. 再实现主流程（fetch(全板块点位+校验) → analyze 两层 → 三表双存储 → export 8 sheet）。
